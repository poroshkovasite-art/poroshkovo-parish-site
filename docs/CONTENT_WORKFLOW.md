# Как добавить материалы Порошкова

Проект: `D:\POROSHKOVO_PARISH_WORK\site`. Меняются только его файлы. История Git сохраняется; `force push` не используется.

## Проверить и просмотреть

1. `npm ci` — зависимости инструментов проверки. Посетителям они не загружаются.
2. `npm run build:editor` и `npm run preview:editor` — локальный редакторский предпросмотр на http://localhost:4174/uk/. Здесь видны все подготовленные разделы и черновики. Выходная папка `dist-editor` **не публикуется**.
3. `npm run build:production` и `npm run check` — публичная сборка `dist`.
4. `npm run preview` — проверить публичную сборку на http://localhost:4173/uk/.
5. Указать `PLAYWRIGHT_CHROMIUM_EXECUTABLE`, если используется установленный Chrome. Запустить `npm run test:browser`, `npm run test:portal`, `npm run test:media`, `npm run test:publication`.
6. После проверки: обычный commit и `git push origin main`. Cloudflare Pages автоматически собирает `npm run build:production`, выход `dist`. Проверить фактический сайт и совпадение файлов через `npm run verify:deployment`.

## Файлы данных

В `content/` подготовлены `documents.json`, `pastor-message.json`, `sacraments.json`, `first-visit.json`, `youth.json`, `camps.json`, `social-ministry.json`, `parish-activities.json`, `community-stories.json`, `support.json`.

У каждой записи: уникальный `id` латиницей, двуязычные `title` и `description`, `category`, массив `photos` с ID из `photos.json`, `date` или null, `source`, `verified_on`, `verification_status`, `publication_status`.

Статусы: `draft` — черновик; `needs_confirmation` — ждёт подтверждения; `approved` — разрешён к публикации; `published` — редакционная отметка о фактической публикации после проверки деплоя. Сборщик допускает два последних статуса, только если оба текста заполнены, источник указан, проверка подтверждена (`verification_status: "confirmed"`) и есть дата проверки. Пустая запись со статусом approved вызывает ошибку сборки. Перед изменением статуса раздела заполните записи. У раздела верхний `publication_status` также должен быть approved/published.

Главная и меню автоматически показывают готовые разделы. Индекс документов доступен с честным уведомлением, пока файлов нет. Остальные пустые направления скрыты; их можно видеть только в локальном редакторском предпросмотре. Никакие черновые JSON не копируются в `dist`.

## Документы

Исходные сканы храните **вне репозитория и public**, например `D:\POROSHKOVO_PARISH_WORK\private-materials\documents`. Проверьте персональные идентификаторы, подписи, адреса, данные третьих лиц и разрешение на открытое размещение. Подготовьте отдельную публичную PDF-копию. Поместите только её в `approved-documents/neutral-name.pdf`; в записи укажите `public_file: "documents/neutral-name.pdf"`, дату выдачи `issued_on`, `issuer.uk/en`, описание, `publication_permission: true`, `privacy_reviewed: true`, `privacy_reviewed_on`. Для опубликованной записи все эти проверки обязательны. В сборку копируются только привязанные и одобренные PDF; случайный файл в approved-documents не публикуется. Учтите: сам GitHub-репозиторий публичный, поэтому даже туда нельзя добавлять непроверенные оригиналы.

Карточки имеют категории, просмотр PDF в новой вкладке системным просмотрщиком и отдельную загрузку. Это наиболее надёжный вариант на телефоне; отдельный тяжёлый PDF-движок не используется.

## Слово настоятеля

Нужны утверждённые имя и титул, портрет (ID в photos), собственный текст приветствия, разрешение цитировать его от имени священника и контакт. Не использовать фотографию с Литургии как личный портрет без подтверждения. Заполните `full_name`, `church_title`, `portrait_id`, `body`, `contact_phone`, `quote_permission`.

## Истории, молодёжь, социальное служение

Шаблоны уже имеют тематические заголовки. Заполните фактический рассказ и источник, добавьте фотографии с разрешениями. В историях `quote` заполняется только реальной цитатой, `author_name` выводится только с `author_permission: true`. Чувствительные сведения о военных, семьях погибших, пациентах и получателях помощи не публикуйте без отдельного разрешения. Духовная помощь не описывается как лечение. Для лагерей нужны подтверждённые даты, программа, организаторы, контакт и согласия на фото детей. Не заполняйте отсутствующие даты приблизительными значениями.

## Помощь парафии

В `support.json` — направления помощи, несколько `accounts`, отдельные `reports`. Для каждого счёта нужны официальный получатель `recipient`, IBAN, банк, валюта, назначение платежа; SWIFT при необходимости. Требуется `financial_confirmation: true` и общий допуск записи. IBAN проверяется по контрольной сумме. Страница появляется только при готовом содержании и подтверждённом счёте. Пока счетов нет, публичных платёжных кнопок нет. Кнопка копирования готова для подтверждённых счетов.

## Фото и календарь

Главная фотография закреплена: `site.hero_photo_id: "divine-liturgy"` — священник за престолом возле чаши. Последний логотип используется в шапке, подвале и favicon. Для новых фото нужны WebP-варианты, реальные размеры, alt и подписи UA/EN, авторство/источник/разрешение. Подтверждение владельцем согласий для предоставленных фотографий детей получено 29.10.2026.

Календарь: `content/calendar/index.json` и `content/calendar/2026/{church,eparchy,parish}.json`. Сейчас это **выборка** проверенных дат 2026 года: 34 церковные записи и 26 епархиальных событий. Это не полный ежедневный богослужебный календарь. Приходских дат пока нет. Никаких данных 2026 года не переносить на 2027. Добавление года требует отдельной проверки источника и пасхального цикла. Хранятся ссылки на чтения, полные тексты Библии не копируются. Обновление ручное по официальным страницам МГКЄ; автоматического парсинга нет. Для календарных записей используется `status: "confirmed"`, год, source_url и verified_on. `.ics` допускается только для таких записей. Многодневные события имеют включённую конечную дату в JSON и исключённую следующую дату в ICS.

## Карта и приватность

Владелец подтвердил точную булавку 48.670772, 22.752723. Google выдаёт координатную точку без названия организации; не объявлять её проверенной карточкой компании. Встраивание получено через Share → Embed. Короткая ссылка хранится для открытия карты, маршрут ведёт к тем же координатам. Карта обращается к Google только после нажатия посетителем «Завантажити карту»; privacy-текст обновлён. Не заменять точку юридическим адресом.

## Что нужно предоставить

- Утверждённое приветствие, имя/титул и портрет настоятеля.
- Декрет назначения, разрешённые церковные документы, регистрационный документ, устав при разрешении, другие официальные PDF.
- Регулярные богослужения и Матері в молитві уже подтверждены интервью 29.10.2026. Для нового наполнения нужны часы катехизации и отдельные сезонные/праздничные объявления с подтверждением ответственного.
- Реальные программы, сроки и организаторы катехизации, лагерей, социального служения, паломничеств; фотографии с согласиями.
- Реальные истории с текстами, цитатами и авторскими разрешениями.
- Подтверждённые банковские реквизиты, назначения платежей, направления помощи и разрешённые отчёты.
- Для исторических рассказов: архивное фото старой церкви св. Николая, точное фото села и лицензированный пейзаж края. Пока используются типографические карточки, без подмены изображений.
