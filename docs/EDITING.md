# Как обновлять сайт

## Тексты и перевод

Редактировать `content/pages.json` и `content/ui.json`. В каждом текстовом поле есть `uk` и `en`; обновлять обе версии. Существенный факт связывать с записью в `sources.json`, указывать URL, дату извлечения и статус. История хранится в `content/history.json`: запись содержит двуязычный текст, период, дату и сведения об источнике. Спорные сведения не добавлять как подтверждённые.

## Расписание

`content/schedule.json` хранит старое справочное расписание в `historical_reference_only`; эта часть никогда не выводится на сайт. Для действующего расписания заполнить `services` по `templates/confirmed-schedule.json`, поставить дату `confirmed_on` и `verification_status: confirmed` только после согласования. Поля `day` и `name` содержат оба языка. Для праздничной заметки добавить запись в `announcements` со статусом `confirmed` и настоящей датой. Неактуальные объявления удалять из массива.

## Новости

Скопировать образец `templates/news-item.json` в массив `content/news.json`. Удалить `_instructions`, заполнить реальную дату ISO, URL источника/подтверждения, `extracted_on`, заголовок, краткое описание и абзацы на двух языках. Статус `confirmed` ставить только после проверки. Slug — строчные латинские буквы, цифры и дефисы. Перед первым включением заполнить `description` и `intro` для страницы `news` в `pages.json`. Генератор создаст страницу списка, отдельную страницу новости и её языковую пару; новая публикация войдёт в sitemap.

## Фотографии

1. Поместить оригиналы в `../photos/originals_readonly/`; сохранить оригинальные имена и контрольные суммы. Не менять оригиналы.
2. Заполнить `../photos/photo_manifest.csv`: автор, разрешение, согласие на публикацию детей, дата/описание только при подтверждении, назначение. Не публиковать чувствительные надписи и личные документы.
3. Обычной обработкой без генеративной перерисовки создать WebP (обычно 640, 960, 1920 px по ширине, без увеличения исходника). Сохранить версии в `../photos/webp_ready/` и `assets/photos/`. Имена — `<id>-<ширина>.webp`. Поле `widths` должно содержать реальные ширины файлов; небольшое фото не выдавать за 1920 px.
4. По `templates/photo.json` заполнить `content/photos.json`. Обязательны `alt`/`caption` на двух языках, автор, реальные размеры, статус и права. `publication_status: approved` и `rights_confirmed: true` разрешают показ.
5. Для первого включения галереи заполнить `description` и `intro` для `gallery` в `pages.json`. Для обложки указать `hero_photo_id` в `site.json`. Галерея имеет фильтры, модальное увеличение, стрелки, Escape и возврат фокуса.

При отсутствии готового изображения оставить типографическую композицию. Снимки из ISF/NAU и Google Maps не использовать. Контактные листы — в `../photos/contact_sheets/`.

## Контакты и карта

В `site.json` заполнять `contact.address` как объект `{uk, en}`, остальные поля — строками. Точный URL карты и `embed_url` должен подтвердить приход. `verification_status: confirmed` включает контактный блок, `tel:`, `mailto:`, карту с lazy loading и маршрут. Допустимый хост iframe — `https://www.google.com`; при иных вариантах карты сначала проверить CSP. Контакт епархии нельзя выдавать за контакт парафии.

## Поддержка и люди

В `donations` вносить только официально утверждённые реквизиты. После `verification_status: confirmed` и заполненного IBAN нужно также заполнить двуязычные `intro` и `description` страницы `support`. Список людей — `people.json`; неизвестных лиц по фотографии не идентифицировать. Перед подтверждением нынешнего настоятеля обновить источник и примечание компонента TeamCard.

## Проверка после изменения

`npm run build`, затем `npm run check`, затем запустить preview и `npm run test:browser`. Просмотреть скриншоты в `../audit/` вручную. Тесты проверяют сетку на 9 ширинах, меню, языки, карусель, историю и доступность. В текущем основании галерея проверяется изолированным тестовым набором, который не попадает в сборку. После добавления реальных фото дополнительно проверить их содержание, пропорции и разрешения.
